# Notificação push de queda de Tier na Liga

O ADR-0010 já tinha cogitado uma notificação de "Sequência em risco" e descartou por exigir "capability nova (permissão de OS, SDK, UX de opt-in, agendamento) sem nenhuma infraestrutura de push hoje no projeto", registrando o item como pendência de backlog. Decidimos (sessão de `/grill-with-docs`, 2026-09-08) reabrir essa pendência agora, com um gatilho diferente: **queda de Tier** (não Sequência) — quando um dispositivo desce de Tier na Liga (Ouro → Prata, por exemplo) ao fim da semana. Divisão não serve como gatilho: é recalculada do zero toda semana dentro do Tier (migration `0004_league.sql`), não é uma identidade persistente comparável entre semanas — só o Tier, gravado em `league_placements`, permite dizer "você caiu" de um jeito que faz sentido pro jogador.

A infra de push nasce **genérica** — token por `device_id`, despacho via Expo Push Notification Service (`expo-notifications` no cliente, Expo Push API no servidor — natural pro stack 100% Expo/RN, evita lidar direto com certificados APNs/FCM) — mas só o gatilho de Queda de Tier é implementado nesta rodada. Sequência em risco e o lembrete de pausa (cogitado no premortem de lançamento) ficam de backlog, reaproveitando essa mesma infra quando forem especificados.

O ponto que exige mais cuidado é que **a Liga hoje resolve o Tier de forma preguiçosa**: `get_league_leaderboard` só calcula o Tier da semana nova de um dispositivo na primeira consulta daquela semana (comentário explícito na migration: "sem job agendado"). Uma notificação push, por definição, precisa alcançar o jogador antes dele abrir o app — ou seja, antes de qualquer consulta preguiçosa acontecer. Resolvemos isso com um **job semanal novo** (ex.: segunda 00:05 UTC) que reaproveita a mesma função `_resolve_league_tier` já existente: para todo dispositivo que tinha posição na semana anterior, calcula o Tier novo, grava em `league_placements` (mesma idempotência `on conflict do nothing` da RPC), compara com o Tier anterior e dispara push nos casos de queda. A RPC preguiçosa **não muda** — continua funcionando exatamente como hoje, como rede de segurança para qualquer dispositivo que o job não tenha coberto (corrida no instante exato da virada de semana, por exemplo). É uma adição à arquitetura da migration 0004, não uma reversão dela.

A permissão do sistema operacional é pedida contextualmente: na primeira vez que o dispositivo entra na Liga (primeira resposta de `get_league_leaderboard` com `active: true`), nunca no cold start — antes disso não existe Tier nenhum pra "cair", então pedir permissão seria sem contexto. Um soft-ask dentro do app (banner/botão na `DailyChallengeScreen`) precede o prompt nativo, pra não gastar a única tentativa de permissão do iOS num momento errado. Tocar na notificação navega direto para a `DailyChallengeScreen` (seção Liga) via um listener de resposta de notificação que chama a action `openDaily` já existente — não só abre o app na Start Screen. A copy nomeia o Tier novo por nome (ex.: "Você caiu para Prata"), sem linguagem de urgência manipuladora — consistente com o pilar de competição social justa do GDD.

> **Atualização (2026-09-08):** soft-ask removido (`PushSoftAskBanner` e toda a lógica associada, `shouldShowPushSoftAsk`/`push.softAskState`). A permissão do SO passa a ser pedida direto — prompt nativo puro, sem texto customizável nosso antes — no cold start absoluto da primeira sessão, antes até do onboarding geral do jogo, independente de a Liga já ter ativado pro dispositivo. Decisão de produto: UX "como qualquer app" (pede uma vez, cedo), aceitando conscientemente a taxa de opt-in menor que pedir sem contexto traz — o trade-off que a decisão original evitava deixa de ser prioridade. Instalações que já responderam via soft-ask não são reafetadas: o SO não reabre um prompt nativo pra uma decisão já tomada, então chamar a permissão de novo no cold start é um no-op pra quem já decidiu.

## Considered Options

- **Aviso só dentro do app, sem push real** (banner na próxima abertura) — mais barato, sem infra nova, mas só alcança o jogador se ele já decidiu abrir o app sozinho — não move D7/D30 do jeito que uma notificação de verdade moveria. Descartada.
- **Infra de push estreita, só pro caso de Queda de Tier** (sem generalizar) — evita pensar em reuso agora, mas a peça cara/arriscada é a infra (token, permissão, dispatch), não o conteúdo da mensagem; construir estreito significaria refazer esse trabalho do zero na próxima notificação (Sequência em risco, lembrete de pausa). Descartada.
- **Substituir a resolução preguiçosa da RPC pelo job** (job vira única fonte de verdade, RPC para de calcular) — mais simples de raciocinar, mas remove a rede de segurança pra dispositivos que o job não cobriu, e reverte uma decisão da migration 0004 sem necessidade real (o job já resolve o problema de "chegar antes do jogador abrir o app" sem precisar remover o caminho preguiçoso). Descartada.
- **Certificados APNs/FCM próprios**, sem o serviço de push da Expo — mais controle, mas exige gerenciar credenciais de duas plataformas diferentes sem ganho nenhum pro caso de uso atual (mensagens simples, sem rich media). Descartada.

## Consequences

- Schema novo no Supabase: tabela de push token por `device_id` (token mais recente sobrescreve o anterior — sem histórico, mesmo espírito de `players`/`league_placements`).
- Job agendado novo (Edge Function + `pg_cron` ou equivalente) — primeira peça de infra agendada do projeto; tudo antes disso era `on-demand`/lazy via RPC.
- `services/` ganha um serviço novo de push (registro de token, escuta de resposta de notificação) — mesmo padrão de porta/adapter já usado por `services/supabase.ts`, `services/ads.ts`, `services/updates.ts`.
- `DailyChallengeScreen` ganha o soft-ask de permissão quando a Liga ativa pela primeira vez para o dispositivo.
- Este ADR fecha a decisão de design, não a implementação — segue para `/to-spec` → `/to-tickets` → `/implement` no pipeline normal.
- Segue de backlog, reaproveitando esta mesma infra quando especificados: notificação de Sequência em risco (ADR-0010), lembrete de pausa não-bloqueante (premortem de lançamento).
